# Release evidence policy

This is the permanent release rule for every version. The README, security
policy, ownership notice, donation addresses, and comparison wording are
evergreen: a normal source update must not rewrite them. A release changes the
version in `pubspec.yaml`, its source, its SBOM, and its release artifacts.

The required GitHub verification workflow runs
`scripts/check_release_evidence.py`. It rejects a source version unless
`docs/releases/<major>.<minor>.<patch>.md` exists, names the exact version
(including its build suffix), and contains the marked test-result table. This
applies equally to human and AI-authored changes.

## Required evidence for a confirmed version

Before describing a version as **confirmed**, a maintainer must run these
commands from its tagged source commit and retain their unedited terminal
output with the release:

```bash
flutter analyze --no-pub
bash scripts/test-suite.sh
bash scripts/secret-scan.sh
(cd verification && npm ci && node verify.cjs)
python3 scripts/dependency-audit.py
python3 scripts/sbom.py --out docs/SBOM.json
git diff --exit-code -- docs/SBOM.json
bash scripts/build-deb.sh
BNB_RELEASE_DEB='/absolute/path/to/x-wallet-<version>-amd64.deb' \
  bash scripts/release-check.sh
```

The signed tag, `.deb`, `.asc`, `SHA256SUMS`, SBOM, and command transcript
must all name or unambiguously identify the same source revision. A clean
Ubuntu install-and-launch test, upgrade/uninstall check, and data-preservation
check are required before public release.

## Machine-readable evidence

The single source of truth is `release/manifest.json`, generated by
`scripts/release_manifest.py`. It records the version, Flutter/Dart toolchain,
lockfile hashes, SBOM hash, test inventory summary, Android signing status, and
the committed evidence bundle (if any). It contains no result that a command
did not produce. The exact commit is bound by `release/evidence.json`, not
embedded in a document that the commit itself contains.

## Reproducibility

`scripts/reproducibility-check.sh` builds the same source twice at a fixed
absolute path, with `SOURCE_DATE_EPOCH=0` and timestamp-free gzip, and compares
both the archive and the file manifest. On 2026-11-06 two clean builds at
`/tmp/bnb-repro-final` produced identical archive
`0e3cb4c1465ad0ac35f8104560ed623b79c4d7194bdb625119f858de1d0e8d4c`.

This passes only under the documented fixed-path constraint: Flutter embeds
absolute paths in `libapp.so` and plugin `.so` files, so builds at different
paths differ. An independent-machine proof is still required. Never describe a
different-path build or a provenance attestation as reproducible.

`release/checks.json` (gitignored) holds per-commit results recorded by
`scripts/record_check.py`; `release/artifacts.json` holds artifact hashes.
A published release may commit `release/evidence.json`, which must name the
exact `sourceCommit`. `scripts/release-gate.py` evaluates those records and
prints `VERIFIED`, `PARTIALLY VERIFIED`, `INCOMPLETE`, or `FAILED`.

Generated views (`docs/GENERATED_STATUS.md`, the README status block, and the
test matrix counts) must be regenerated and committed whenever their inputs
change. CI rejects drift; never hand-edit a generated block.

A result from another commit, another artifact, or another machine is not
evidence for this release. A canceled check, timeout, or OOM is not a pass.

A release may add an **evidence-only** follow-up commit (for example
`release/evidence.json`, the regenerated manifest, and generated docs). The
bundle's `sourceCommit` names the commit the checks actually ran on. The gate
accepts that ancestor only when every later change is under `docs/` or
`release/` or is `README.md`; any source, test, script, or dependency change
invalidates the bundle.

## Status vocabulary

- **Confirmed**: every required command exited zero, the artifact matched its
  checksum and signature, and the clean-install checks are recorded.
- **Partially verified**: only the listed checks passed. It must never be
  presented as a substitute for a full release gate.
- **Not tested**: no result was captured. Silence, a stalled process, or an
  interrupted run is not a pass.

No score, AI analysis, self-assessment, test result, or package signature can
guarantee safety for a real-money wallet. Independent review remains required
for a credible large-value security claim.
